# Checklists — 32 Demo and Presentation

[⬅ Back to README](README.md)

## Pre-Session QC
- [ ] Fold-in vs. dedicated-session decision made and documented
- [ ] Deck/outline mirrors the approved solution map (Stage 31), not an ad hoc pitch
- [ ] Relevant case studies (Stage 31) woven in, not dumped as a separate slide

## Session QC
- [ ] Each deliverable explicitly connected to the specific problem it addresses
- [ ] Process made tangible (onboarding, cadence, example deliverables), not left abstract
- [ ] Questions/objections actively invited, not just tolerated if raised

## Post-Session QC
- [ ] Questions raised logged in CRM
- [ ] Any needed proposal adjustments identified before Stage 33 drafting begins

## Duplicate / Accuracy / Completeness Checks
- [ ] No conflicting session notes for the same opportunity
- [ ] Session type (fold-in/dedicated) accurately reflects what actually happened
