# M03 — Checklists

## Pillar Definition Checklist

- [ ] Each pillar traces back to a real service line or grouping of service lines (Method 1 in `methods.md`), not an arbitrary content theme
- [ ] Where more than one internal doc already proposed pillars, they've been reconciled into one list (Method 2) rather than left inconsistent across channels
- [ ] Each pillar has a target keyword or clear search intent checked (Method 3), or is explicitly flagged as an authority/trust pillar not primarily driven by search demand
- [ ] Each pillar has a content-type mapping (Method 4) — which formats it's naturally suited to
- [ ] Messaging framework (headlines, elevator pitch, CTA set) checked for consistency with M01's tone-of-voice guide

## Pillar Balance Checklist (rule-of-thumb, pending real data)

- [ ] No single pillar represents more than roughly half of scheduled content in any given period, unless there's a deliberate campaign reason (e.g., a case-study push after a client win)
- [ ] Every pillar appears at least once per publishing cycle once volume allows it — a pillar that never gets covered isn't functioning as a pillar
- [ ] Balance re-checked against actual publishing history once M08/M09 have enough volume for the check to be meaningful (see `automation.md` Tier 3)

## Downstream Handoff Checklist

- [ ] Pillar list is reflected in M09's Content Brief template as the option set for the "pillar" field
- [ ] M08's calendar tags each scheduled piece with its pillar
- [ ] M17's Email Content Pillars are reconciled with this stage's pillars rather than run as a separate, inconsistent list

## Periodic Review

- [ ] Pillars re-reviewed if M01 (positioning) or the service lineup itself changes
- [ ] Keyword validation re-run periodically — search demand behind a pillar can shift even if the pillar itself stays relevant
