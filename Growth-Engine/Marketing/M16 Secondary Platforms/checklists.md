# M16 — Checklists

QC gates for Secondary Platforms (Pinterest, Threads, WhatsApp Broadcast), following the Implementation Plan's standing rule (§6): every AI-drafted
content step keeps a human-review checklist gate before publish.

## QC-M16-01 — Draft Review (before scheduling)

- [ ] Draft matches the content mix ratio for this week (README.md §3) — not overweighted to one type
- [ ] Format matches the rotation (README.md §2) — e.g. LinkedIn: is this slot supposed to be a
      carousel, not a text post?
- [ ] No fabricated stats, client names, or results not already approved for public use
- [ ] CTA present and matches README.md §2's primary CTA
- [ ] Hashtags/tags follow the stage's convention (README.md §2) — or are flagged if the convention
      isn't yet defined for this platform
- [ ] Tone matches the platform's stated audience (README.md §1)
- [ ] If AI-drafted: a human has read the full draft, not just skimmed the first line

## QC-M16-02 — Publish Confirmation

- [ ] Post published at (or near) the scheduled time in README.md §2
- [ ] Post URL logged to the tracker (Airtable/Notion) for M21
- [ ] Any broken links, missing images, or formatting errors caught within 1 hour of publish

## QC-M16-03 — Engagement Follow-Up

- [ ] Comments/DMs reviewed and responded to within 24 hours (per the platform's stated CTA)
- [ ] Any qualified interest logged for the M22 bridge (manually, until M22's automation exists)
- [ ] No auto-replies sent without human review, per the automation.md non-goal

## Platform-specific checklist items

- [ ] WhatsApp Channel: confirm the post is value-first, not promotional, per the platform's explicit "never hard-sell" rule (README.md §2)
- [ ] Pinterest/Threads: do not run these two platforms through this checklist as if they were fully scoped — flag any activity on them for review against the source-coverage gap in README.md before treating it as standard process
