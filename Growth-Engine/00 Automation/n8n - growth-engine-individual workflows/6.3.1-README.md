## Built as literally specified — flagging the tool-stack overlap, not resolving it

The tracker row names Slack → Linear → Postgres explicitly, so that's what's built. This is a different function than Chatwoot (customer-facing helpdesk widget, still undecided per §0.3) — this session is internal issue tracking off a Slack message. Flagging that these two may eventually need to be reconciled into one support system, but that's a decision for Nivy, not something resolved here.

## Test Checklist

1. Post a test message in the mapped Slack channel → confirm a Linear issue is created with the message text.
2. Reply in a thread (not a root message) → confirm it's filtered out, no duplicate ticket.
3. Post as a client whose email happens to match `clients_master.email` → confirm `support_ticket_count` increments (this will require faking the match for a real test, since the Slack-user-to-email mapping doesn't exist yet).
4. Post as an unmatched user → confirm it lands in `Log Unmatched Ticket`, not silently lost.
